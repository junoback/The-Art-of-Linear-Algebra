## 1. 章節 md 檔案結構（每章一檔）

每個章節 md 的標頭與段落順序：

```markdown
# 章節編號. 章節中文標題（English Title）

> **原書頁碼：** p.X–p.Y
> **對應 .tex 段落：** `<檔案>` 第 N–M 行
> **本章圖數：** N
> **本章 VizMark 數：** N（⭐⭐⭐ × n_a / ⭐⭐ × n_b / ⭐ × n_c）
> **狀態：** [ ] 撰寫中 / [x] 已完成 / [ ] 校對中

---

## 章節摘要（200–400 字）

（用繁體中文總結本章要傳達的核心觀念。術語第一次出現時括號標英文。）

---

## 數學要點

> 公式直接保留 LaTeX（用 `$$ ... $$` 包），方便後續 Python 程式碼直接複製或轉 SymPy。

$$
A = \begin{bmatrix} \cdots \end{bmatrix}
$$

## 圖片區（逐張）

（每章 N 張圖，每張一個 `### Figure X.Y` 子區塊，格式見 §2；圖描述後若該圖有對應 VizMark，緊跟著嵌一個 `VizMark` 引用 block）

## 2. 單張圖描述格式（四欄位 schema）

每張圖固定四個欄位，順序不變。後三欄位對應未來 Python 視覺化的三個層次。

```markdown
### Figure X.Y: 圖中文標題（English Caption from book）

**圖檔：** `docs/book/figs-png/<name>.png`（原始 EPS：`figs/<name>.eps`）
**原書頁碼：** p.X
**所屬章節：** §X.Y

#### 視覺結構 (Visual Structure)

文字描述這張圖的構圖：
- 整體布局（左右 / 上下 / 流程箭頭方向）
- 主要圖形元素（方塊、向量、箭頭、座標軸）
- 顏色 / 線型 / 標記符號的意義
- 視覺上要讀者「先看哪裡、再看哪裡」的引導

字數約 100–250 字，目標：盲讀者（看不到圖）也能在腦中重建畫面。

#### 數學內容 (Mathematical Content)

- 圖中出現的所有變數 → 對應的數學物件
- 圖中演示的運算或變換 → LaTeX 公式
- 維度標註（$m \times n$、向量在 $\mathbb{R}^n$ 等）

範例：
$$
\mathbf{a}_1 \in \mathbb{R}^m, \quad \mathbf{a}_2 \in \mathbb{R}^m, \quad
A = \begin{bmatrix} \mathbf{a}_1 & \mathbf{a}_2 \end{bmatrix} \in \mathbb{R}^{m \times 2}
$$

#### 直覺解讀 (Intuition)

200–400 字的解說：
- 此圖想讓讀者「悟到」什麼概念
- 與前後章節觀念的連結
- 容易誤解的點 / 常見初學陷阱
- 必要時對比「另一種看法」（呼應原書「N Ways」風格）

#### 視覺化機會（VizMark 引用）

> 此欄位**取代**舊版的「互動化提示」。如果此圖值得做互動視覺化，插一個 VizMark 引用 block，並在章末「## 視覺化劇本」段寫對應 VizScript。
> 格式規範見 `VIZ_SCHEMA.md`。

範例：

```markdown
> 🎬 **VizMark-01** [切換視角] ⭐⭐⭐
> **位置：** 本圖 / §1.2 ViewingMatrix-4Ways
> **核心概念：** 同一矩陣的 4 種等價觀看視角
> **互動梗概：** 按 4 個視角鈕，主圖即時切換並動畫過渡
> **詳見劇本：** VizScript-01（章末）
```

如該圖無視覺化價值（純示意 / 表格 / 流程圖等），此小節寫「（無 VizMark — 純說明圖）」即可，不必勉強加。
```

## 3. 風格與用語規範

### 3.1 語言與術語

- **主要語言：** 繁體中文
- **第一次出現的線代術語：** 中文 + 括號英文，例如「行空間 (column space)」
- **第二次起：** 可只用中文或只用英文，依該段語境
- **核心術語對照（永久保留中英並列）：**
  - matrix 矩陣
  - vector 向量
  - row 行 / column 列（**注意：中文「行」「列」與英文 row/column 翻譯方向不唯一。本專案採華文主流慣用（含中國大陸、日本、多數 Python / 線代中文文件）：column = 列（直立）、row = 行（橫躺）。台灣本土數學教科書傳統採相反方向（column = 行、row = 列），讀者若來自此背景請花一兩分鐘調整。**）
  - column vector 列向量（直立）/ row vector 行向量（橫躺）
  - column space 列空間 $\mathbf{C}(A)$ / row space 行空間 $\mathbf{C}(A^{\mathrm{T}})$
  - rank 秩
  - subspace 子空間
  - basis 基底
  - linear combination 線性組合
  - dot product 點積 / 內積 (inner product)
  - factorization 分解
  - eigenvalue 特徵值、eigenvector 特徵向量
  - singular value 奇異值

### 3.2 公式

- 行內公式：`$a + b$`
- 區塊公式：`$$ ... $$`
- 矩陣優先用 `\begin{bmatrix}`
- 向量加粗：`\mathbf{a}`（不用 `\bm`，跨平台相容性較好）

### 3.3 圖片連結

- 一律用相對路徑指向 `figs-png/`：`![caption](figs-png/<name>.png)`
- 不直接嵌 .eps（瀏覽器顯示不了）

### 3.4 引述原書

- 若需引用原書文字，限制在「短句、必要、有引號」三條件
- 大段落改寫為自己的中文敘述 + 數學內容（事實性數學陳述不受著作權限制）
- 圖片描述全用自己的分析語言，不逐字翻譯原書圖說

#### 3.5.2 cell 像素尺寸規範

無單一強制標準（各 VizScript 視窗大小不同），但**單一 VizScript 內必須一致**。常見組合：

| 矩陣展示尺寸 | 適用場景 |
|---|---|
| `60×60 px` cell | 小矩陣展示（2×2 / 3×3 範例 walkthrough）|
| `48×48 px` cell | 中矩陣展示（4×4 / 5×5 互動）|
| `20px` cell | 大矩陣 / Mona Lisa demo（64×64 像素圖）|

#### 3.5.3 動畫時間規範

無單一強制標準（依互動類型），但**寫法統一無空格**：`200ms`、`800ms`，不是 `200 ms`。

常見錨點（S07–S10 累積經驗）：

| 時間 | 適用場景 |
|---|---|
| `50ms` / `100ms` | 即時反饋（slider 拉動）|
| `200ms` ⭐ | 標準切換 / hover 過渡（**全書最常用**）|
| `500ms` / `600ms` | 視角切換 / dashboard mode 切換 |
| `800ms` | 中等動畫（秩 1 累加 step 間隔）|
| `1500ms` / `3000ms` | 完整 walkthrough 動畫單步 |

#### 3.5.4 3D 視角預設規範

凡使用 3D 視窗的 VizScript（涵蓋 ch03 / ch05 / ch06d / ch06e / ch06f / App C 等大量章節，全書 109 次 3D 提及），**預設視角統一：**

```
elevation = 25°   (上下傾斜，從略上方往下看)
azimuth   = -60°  (左右旋轉，預設斜左視角)
```

**設計理由：**
- elevation = 25° 介於完全俯瞰（90°）與正側視（0°）之間，能同時看到 X-Y 平面結構 + Z 軸高低
- azimuth = -60° 讓 X 軸偏左、Y 軸偏右，3 軸都不重疊，立體感最強
- 與 matplotlib mplot3d 預設 (elev=30, azim=-60) 接近，便於 Python 實作

**允許覆蓋情境：**
- 純俯瞰示意（如顯示「列空間是個平面」用 elev=89°）— 在該 VizScript 內明文聲明
- 預設視角對特定矩陣不利（如極端瘦長矩陣）— 在該 VizScript 內明文聲明

**互動行為：**
- 拖曳視窗背景（不是箭頭）做相機旋轉
- 滾輪縮放
- 雙擊重設回預設視角

### 3.6 背後觀念 callout 規範（S12-S15 確立）

> 本節是「**主章 / 附錄連結到 Appendix D 背後觀念層的 callout 格式統一規範**」。S12-S15 累積建立的 15 個 callout（覆蓋 foreword + ch01-ch06f + 3 附錄 = 全書 16 個內容 md，每個都有一個 callout）展示了一致的格式 — 此規範把它寫成標準，供未來新增章節 / 附錄時參照。

#### 3.6.1 觸發時機

**每個主章 / 附錄都應在「章節摘要」段末附一個 callout**，連結到 [appendix-D-why.md](appendix-D-why.md) 的對應 Q&A 條目。這讓讀者讀完章節摘要、開始進入「數學要點」之前，先看到「**這條規則為什麼長這樣**」的背後問題與探索入口。

例外：[appendix-D-why.md](appendix-D-why.md) 本身**不需**callout（它就是 callout 的目的地）。

#### 3.6.2 插入位置（精確）

callout 緊接在「章節摘要」內容段末，**位於空行之後、`---` 分隔線之前**。具體結構：

```markdown
## 章節摘要

[章節摘要正文一段或多段]
                              ← 空一行
> ### 💡 背後觀念：[hook 問題]
>
> [動機段落 ~80-150 字]：
>
> - **[QNN：標題](appendix-D-why.md#qNN)** — [短摘 ~100-300 字含 hook]
> - **[QMM：標題](appendix-D-why.md#qMM)** — [短摘]
                              ← 空一行
---

## 數學要點
```

#### 3.6.3 格式模板（quote block）

callout 整體用 markdown blockquote（`>` 起頭），結構：

1. **第 1 行**：`> ### 💡 背後觀念：[hook 問題]` — 💡 emoji + H3 標題層級 + 一句**問句**形式的 hook（讀者讀完摘要可能會問的「為什麼」）
2. **第 2 行**：`>` 空行
3. **第 3 行**：動機段落 — 用 ~80-150 字闡述「**這個章節背後最深的『為什麼』是什麼**」+ 「**3-layer 涵蓋 ① 歷史 / ② 推導 / ③ 昇華**」+ 「**:** 」結尾過渡到 bullet list
4. **第 4 行**：`>` 空行
5. **第 5+ 行**：bullet list（`> - **[QNN：標題](anchor)** — 短摘`）— **1-4 條 Q&A 連結**（主章常 1-3 條、§6 章節 / 附錄常 2-4 條）

#### 3.6.4 篇幅規範

| 元素 | 字數範圍 | 範例位置 |
|---|---|---|
| Hook 問句（第 1 行）| 15-40 字 | ch06f Q19 callout：「SVD 為什麼能成為全書集大成？」|
| 動機段落（第 3 行）| 80-150 字 | ch06e Q18 callout：「對稱矩陣 $S = S^{\mathrm{T}}$ 的特徵向量自動正交、特徵值自動實 ...」 |
| 每條 Q&A 短摘 | 100-300 字 | 含「① 歷史人物 + 關鍵年份 + ② 核心推導機制 + ③ 跨領域應用 / 名言」三段壓縮 |
| callout 整體 | 250-700 字 | §1-§5 主章常 250-400 字、§6 章節 / 附錄常 400-700 字 |

#### 3.6.5 Hook 設計準則

- **問句形式**：「為什麼...？」「怎麼...？」「哪裡冒出來？」— 避免陳述句
- **指向章節核心抽象**：不重述章節內容，**而是問章節內容背後的「為什麼」**
- **與 Q&A 標題相關但不重複**：Q&A 標題是「為什麼有解這個問題」、callout hook 是「讀者讀完章節想問的版本」
- **使用 Strang LAFE 名言**（如可用）：「Make every matrix look diagonal」「the most important theorem in linear algebra」「the central problem of linear algebra is $A\mathbf{x}=\mathbf{b}$」

#### 3.6.6 Q&A link 選擇

- **必選**：對應本章核心主題的 Q&A（如 ch06e EVD → Q18 譜定理）
- **常選**：與本章相關的「奠基性」Q&A（如 ch06e EVD → Q11 對角矩陣的超能力、Q13 (P4) 三明治）
- **§6 章節 link 數通常較多**：§6 五大分解統合 §1-§5 多個概念，callout 平均 link 數比 §1-§5 高 15%（S14 觀察，自然現象不要強行壓低）
- **附錄 link 數也較多**：附錄重整合不重教學，link 多有助於導覽

### 3.7 逆向設計鏈（R-chain）規範（S19 確立）

> 本節是「**Appendix E 逆向設計鏈 R01-R07 的寫作格式統一規範**」。S19 啟動的「逆向設計視角」是全書**第二骨架**（與 Appendix D 「正向背後觀念」橫切剖析對偶）。每條鏈遵循**5 步反推骨架**，總共擴展為 12 個 Step 段落。本規範把 R01-R02 確立的格式寫成標準，供未來 R03-R07 + 任何後續逆向鏈參考。

#### 3.7.1 觸發時機

任何「**主章 / 附錄某個運算規則或定理可以從『實際問題 + 還原需求』反推**」都應寫成一條 R-chain，集中放在 [appendix-E-reverse.md](appendix-E-reverse.md)，**不是**散在主章。主章只放短 callout 連結到對應的 R-chain。

#### 3.7.2 5 步反推骨架（必有）

每條 R-chain 至少包含這 5 個邏輯步驟：

1. **實際問題（結果需求）** — 工程 / 科學中反覆出現的某類問題；給具體例子（3 個以上典型場景）
2. **物件化（抽離係數與變數）** — 把問題從「方程組 / 自然語言」抽象到「矩陣物件」層次；釐清「對矩陣的合法操作必須對應問題層的合法變形」（**抽離–還原的可逆閉合**）
3. **尋找未知運算 ◯** — 寫下短公式（如 $A \mathbin{\bigcirc} \mathbf{x} = \mathbf{b}$），明確 ◯ 是未知的
4. **閉合需求反推 ◯ 的規則** — 由「還原原問題的需求」**唯一強制** ◯ 必須長什麼樣（具體 → 一般 → boxed 公式）
5. **副產物自動冒出** — 規則確立後，相關性質、概念、定理**全部作為副產物自動冒出**

#### 3.7.3 12 Step 段落（標準擴展）

5 步骨架展開為 12 個 Step 段落，這是 R01-R02 確立、R03-R07 應沿用的格式：

| Step | 段落主題 | 內容要點 |
|---|---|---|
| 0 | 我們在做什麼 | 正向 vs 逆向視角對比（表格）|
| 1 | 實際問題（結果需求）| 一般形式 + 主例題（含具體數字，貫穿全鏈）|
| 2 | 物件化（抽離係數與變數）| 矩陣物件 + 完整解集（如適用）|
| 2 加強 | 對物件的合法操作 | **嚴禁用未推出的運算解釋自己**；只用問題層代數語言；3 ✓ + 3 ❌ 公式可視化；**暗線埋伏**（指向後續鏈兌現）|
| 3 | 尋找一個運算符號 ◯ | 明確「◯ 是未知的」 |
| 4 | 閉合需求反推 ◯ 的規則 | 具體 → 一般 → boxed 公式 |
| 5 | 副產物 1（如維度規則）| 強制反推的形狀 / 維度條件 |
| 6 | 副產物 2（如雙視角）| 同一規則的另一展開方式 |
| 7 | 副產物 3（如列空間 / rank）| 衍生的子空間 / 結構性概念 |
| 8 | 雙路閉合驗證 | 兩條讀法產生相同結果 |
| 9 | 邊界條件 | 線性 vs 非線性 / rank 0 vs rank 1 等的邊界討論 |
| 10 | 昇華 — 完整反推鏈圖 | boxed 流程圖 + 一句總結 |
| 11 | 連結其他 R-chain | 後續鏈如何沿用本鏈副產物 |
| 12 | Strang 鎖核 | Strang LAFE 引言收尾 |

#### 3.7.4 「Step 2 加強」鐵律：禁用未推出的工具解釋自己

這是 S19 與 Back 互動最關鍵的教訓：**寫 R-chain 時，Step 2 加強描述「對物件的合法操作」絕對不可使用尚未在 Step 4 反推出的運算工具來解釋**。

**❌ 反例（S19 第一稿犯的錯誤）：**

> 用「左乘可逆矩陣 M」「elementary 矩陣」「LU 分解」描述合法操作 — 這需要讀者**先懂矩陣乘法**，但矩陣乘法要 Step 4 才被推出，邏輯循環。

**✓ 正例（S19 修訂後）：**

> 用「整條方程乘非零常數」「兩條方程互換」「方程 i 加方程 j 的 c 倍」這些**中學代數會的方程組變形**描述合法操作，A 與 b 的 entry 級同步動作直接寫出 — 不引入任何矩陣乘法概念。

**暗線埋伏：** 若需要承諾「這些操作後面會被統一」，用 quote block 寫一段「等 Step 4 後 X 鏈會兌現」的引導，明確指向**後續**鏈條而**不**在 Step 2 展開。

## 5. 撰寫流程（每個章節 session 適用）

每個章節 session（S02–S10）的工作步驟（**方案 A 整合版**）：

1. 從 `from-tex/en.md` 抓本章的 LaTeX 原始結構（標題、公式、圖片清單）
2. 對照 `from-pdf/en.txt` 確認 PDF 上的純文字（補 pandoc 漏掉的東西）
3. 對照 `from-tex/zh.md` 看簡中版用詞做翻譯參考
4. **看 `figs-png/` 中對應的 PNG 圖檔，逐張寫四欄位描述**
5. **同步掃描視覺化機會：每張圖看完描述後，判斷是否插 VizMark**
   - 命中 §1.3 五種類型之一 → 插 VizMark（章內就近放）
   - 判定優先級 ⭐ / ⭐⭐ / ⭐⭐⭐
6. **章末寫 VizScript：每個 VizMark 對應一個 800 字劇本**
   - 格式遵 `VIZ_SCHEMA.md` §2（13 段）
   - 配色、數字、邊界、驗收標準都明確列
7. 寫章節摘要與數學要點段（最後寫，因為描述完才能精煉摘要）
8. 在 `_merged.md` 對應章節區塊勾選完成 + 填 VizMark 計數
9. 更新 HANDOFF.md 與 CURRENT_SESSION.log

**順序提示：** 第 4-6 步是同一個「閱讀 → 描述 → 標記 → 寫劇本」的連續心智動作，**不要切開**，否則理解會斷層。
